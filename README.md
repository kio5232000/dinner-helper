## V2.1｜AI 成本優化版（2026-11-11）

- 相同且經公開學校午餐 JSON 核對的菜單共用 AI 食譜，快取有效期為七天，內容或提示詞版本改變就會重新生成。
- 快取命中不扣新生成額度；未命中仍限制每來源 IP 每臺灣日 2 次、全站 35 次。
- 透過 D1 原子寫入取得 90 秒生成權，同菜單同時查詢不會重複呼叫模型；其他請求會收到稍後再試的提示。
- 自行輸入或未通過公開學校資料核對的菜單不保存至共用快取，仍可在額度內請求 AI。
- 每日按模型彙總 OpenAI Responses API 回傳的 input、cached input、output token 與有用量資訊的回應數。此為程式端觀測資料，不能取代 OpenAI Usage 官方帳務。
- 手機食譜展開後，食材與料理步驟使用全寬條列，並清楚區分新生成及共用推薦。
- **部署：** GitHub Pages 更新與 Cloudflare Worker 部署分開。必須先在既有 D1 執行 `worker/migrations/0002_cache_usage.sql`，再部署 `worker/src/index.js`，不用建立新資料庫或更換秘密。
- 操作指南：[V2.1 快取升級與驗收](docs/ai-v2.1-upgrade.md)。

## V1.9｜菜單可靠性與手機使用改善（2026-11-10）

- **顯示「本站保存這份菜單」時間**，不把第一次取得菜單誤當學校公布時間；有當日查詢紀錄時，另外顯示「最近檢查來源」時間。
- **家長端「↻ 更新檢查」**：重新載入 GitHub Pages 已同步的 JSON，並刷新今天／明天學校成功數；此按鈕**不會**主動爬取學校網頁。
- **不同供餐商／多種餐別提醒**：Tad Lunch3 若在正確學校及日期的區塊裡發現多個供餐／餐別標籤，JSON 會保存 `menu_options`；網站顯示來源警示與連結，**仍僅顯示一份已通過驗證的菜單**，不宣稱已完整拆解所有餐別。
- **新增兩項回歸測試**：不同餐別必須屬於同一學校同一日期，不能誤把附設幼兒園的餐別提示套給國小。
- 這次沒有擴充學校名單、沒有啟用 AI，也沒有繞過官方 API 的 Cloudflare 存取限制。

**限制：** 多餐別的完整、獨立菜單選擇介面尚未實作；若家長不確定所屬供餐商，請以學校原始午餐頁為準。資料來源是否標出多種選項，依各校網站的可解析結構而定。

### V1.8 新增：學校來源檢測工具

- `scripts/probe_school_source.py`：獨立檢測**一所**候選學校，不改正式白名單，也不寫入菜單。
- 可以填入校名、行政區、學制、官方網址、指定日期；工具先核對教育部學校名錄，限定公開的 HTTPS `*.tn.edu.tw` 網域，再讀取網頁，使用共用 `parse_menu` 驗證完整菜單。
- GitHub Actions `.github/workflows/check-candidate-school.yml` 已提供**手動表單**，從 Actions 選單點 **Run workflow** 即可檢查；不會自動發布檢查未通過的來源。
- 目前的 `scripts/import_tainan_pilot.py` 使用受控白名單，只有正式加入的學校參與每日同步。不同學校可以共用 Tad Lunch3 或首頁午餐格式解析，不必各別撰寫抓取程式。

**命令列範例：**

```bash
python -m scripts.probe_school_source \
  --school 新興國小 --level 國小 --district 南區 \
  --url https://www.sses.tn.edu.tw/index.php --date 2026-11-10
```

### V1.8 新增：同步成功率與觀測報告

- 同步程式繼續產生 `data/tainan-pilot-status.json`，列出每所試點的今日及明日資料狀態。
- `data/lunch-monitor.json` 記錄**本站首次觀測到**的時間、最後檢查時間及菜色變更指紋，不是校方實際上傳時間。
- `scripts/build_coverage_summary.py` 每次同步後產生 `data/coverage-summary.json`，含今日／明日覆蓋率、近七天**有檢查紀錄的平日**成功率、逐校統計。
- 統計只衡量**本系統觀測到的有效菜單**，不代表全臺南學校覆蓋率或孩子實際吃了哪些餐點；測試名單增加也會使歷史比較的分母改變。
- 正式同步工作流程 `.github/workflows/import-tainan-pilot.yml` 在生成資料後執行報告，並提交 JSON 給 GitHub Pages。
- 每次同步保留校名、日期、來源網址，且限制菜單張數，避免混入不同學校或附幼餐點。
- 已加入 `git fetch/rebase` 防止自動更新時的非 fast-forward 衝突；若主分支資料較新，衝突時保留遠端快照，不以舊資料覆蓋。

### 設定的自動同步時間（臺灣）

週一至週五 **06:45、08:45、11:15、13:35**；週日至週四 **19:15** 檢查隔天預告。實際 GitHub Actions 執行可能延遲。

## 目前的限制與下一步

1. 觀察 30 所學校至少一週的**逐日成功率**，再擴充更多學校。首頁已有每日統計，但 30 所全部成功目前只驗證 11 月 10 日這一輪。
2. 有些學校有兩家供餐商、葷素不同菜單，未來要明確分開餐別；**目前解析通常只顯示首套可驗證菜單**，不能宣稱涵蓋所有供餐選項。
3. 釐清學校公開文字與圖片再利用授權；控制同步頻率，遵守公開資訊使用規範。
4. 官方單校每日午餐接口仍可能回 HTTP 403／Cloudflare 驗證。已研究 OpenAPI v1，但那份是**月度開放資料集下載**接口，未經正式授權不可當成每日即時資料服務。
5. 建立來源可靠的家庭菜譜及實際食材用量；之後再以安全後端串接 AI。
